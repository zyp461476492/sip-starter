# 03 学习方法

这份文件不写 SIP 结论（那是 `wiki/` 的事），只写**怎么学**——学 RTP/SDP/ICE 时原样复用。

本方法针对的目标：**亲手实现协议栈**（当前是 SIP → FreeSWITCH-like 组件的信令内核）。
目标变了（比如变成"能排障"或"过认证"），要调整的是"哪几节精读"，不是方法本身。

## 1. 读 spec 的四分类法

任何规范章节，先归到下面四类之一，再决定读法：

| 类型 | 特征 | 读法 |
|---|---|---|
| **骨架** | 讲全流程、有例子与拓扑图 | 先读、反复读，撑起直觉 |
| **状态机** | 有状态图/定时器/表格，实现时逐条照抄 | 精读到能默画、能写代码 |
| **参考手册** | 枚举（头域、错误码、语法） | 当字典查，**绝不通读** |
| **专题 / 可跳** | 垂直领域（安全、加密、注册表、变更记录） | 撞上了再读，或永远不读 |

**判定问题（一句话过滤）**：*这节为哪个里程碑服务？*
答不上来 → 它是参考手册或可跳；答案写着"将来可能有用" → 也算可跳。

分类的实例见 `wiki/specs/rfc3261.md`（28 节 → 服务 α–ε 哪个里程碑）。

## 2. 里程碑怎么切

- **一个里程碑 = 一个能被第三方工具验收的行为**，不是"读完某章"
- 里程碑之间必须是**依赖顺序**：报文 → 事务 → 对话/注册 → 应用（B2BUA）→ 互通
- 反过来做一定返工（先写 B2BUA 再补事务层，等于重写）
- 每个里程碑都要有**外部验收物**：`sipsak`/`sipexer`/`sipp`/Wireshark 的判定，或真实设备的互通

## 3. 验收物分三类，别混

| 类型 | 放哪 | 寿命 | 判定 |
|---|---|---|---|
| **drill** 验证件 | 本仓 `sip/labs/drills/` | 可丢弃 | 可执行、可对照（`cmp`、状态迁移、工具输出） |
| **impl** 实现 | **另仓**（ADR-0004） | 长期 | 产品指标（并发、内存、互通性） |
| **wiki** 知识 | `wiki/` | 长期 | 每条论断有原文锚点 |

drill 的判据禁止出现"理解了""掌握了"。写完 drill 立刻填"我踩到的"——那一栏比 drill 本身值钱。

## 4. 什么时候读原文

- **实现前一刻**，不是实现前一个月。读早了只会记住"大概好像有个定时器"
- 读的时候对着**状态图/报文字段**做笔记，不做章节摘要
- 拿不准的语义 → 进 `wiki/questions/`，不许猜（`AGENTS.md` §3）
- 只在**撞击点**扩展阅读：某个字段的具体语义、某个错误码的触发条件

## 5. 反模式清单（每条都是真实踩过的）

| 反模式 | 为什么错 |
|---|---|
| 从头到尾通读一遍 | 规范前向引用严重（讲 UA 行为时引用后面的对话/事务），线性读会被击穿 |
| 把规范提炼成"摘要"再学 | 摘要会转述 `MUST` 而走形；且一定会压缩掉边缘条款（ACK 两套规则、framing、竞态） |
| 按文档目录排计划 | 目录顺序 ≠ 依赖顺序 |
| 判据写"理解/掌握" | 不可验证 = 没学到 |
| 把实验室验证件当产品 | 验证件只为证明理解，扩成产品会把知识结构拖成代码附属品（ADR-0004） |
| 提前把整份规范灌进 wiki | 编译成本极高，且没被查询过的页面很快过期 |

## 6. 迁移到下一个主题（media）

学 SDP/RTP 时照抄同一套：

1. 先划 MVP：δ 里程碑只需要 **offer/answer 透传 + RTP relay**，不需要转码/混音
2. 分类：SDP 语法是参考手册、offer/answer 状态是状态机、RTP 头是报文层
3. 里程碑：能协商出一路 PCMU 音频并听到声音 → 再谈 RTCP 质量反馈 → 再谈 DTMF/ICE
4. 同样先入库原文（`media/raw/rfc/`）+ 记账到 MANIFEST，再动 wiki
