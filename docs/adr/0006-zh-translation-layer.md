# ADR-0006 中文译文单独一层 `sip/zh/`，一节一文件

状态：current ｜ 日期：2026-11-16

## 背景

英语阅读慢是当前的硬约束：RFC 3261 有 269 页，L0–L3 各阶段都要回读原文，但初期逐句啃英文
会让"建立骨架"这件事拖上数周。需要的不是"一份翻译"，而是**可对照**：先读中文立骨架，
再回英文核措辞，且随时能看出哪一段的中文对应哪一段英文。

三条边界同时成立才有用：

- 中文必须能链回原文的位置（站点已有 `#sec-x.y` 锁点，§chip 全站 105 处依赖它）
- 规范性措辞不许被翻译改写（`MUST` / `SHOULD` 的强度差异是 SIP 语义的一部分）
- 译文必须可增量生产（18 万英文词不可能一次做完），且**原文变化时要能发现译文过期**

## 决定

新增顶层目录 `sip/zh/`，与证据层 `sip/raw/`、编译层 `wiki/` 并列：

```
sip/zh/
  GLOSSARY.md            译法唯一口径（MUST/SHOULD 保留英文、头域名不译等 8 条硬规则）
  README.md              工作流与纪律
  rfc3261/<节号>.md      一节一文件，frontmatter: sec / en_sha / status / translator / date
```

配套：

- `scripts/rfc-sections.mjs`：切节 + `sectionSha()`（唯一实现，构建与校验共用）
- `scripts/zh.mjs`：读入 / 校验（frontmatter、节号存在、`en_sha` 漂移、规范词保留）
- `scripts/zh-check.mjs`（`npm run zh:check`）：体检，规范词被译掉即 **error**
- `scripts/zh-status.mjs`（`npm run zh:status`）：覆盖率报表，决定下一批译哪几节
- 站点 `raw/rfc3261.html` 三态：**中文（原文折叠）/ 原文 / 对照**，默认中文；未译节自动退化显示英文并标「未译」
- 状态机 `pending → draft（agent）→ reviewed（人）`；**agent 不许自己标 reviewed**

`en_sha` 是每节英文正文的哈希（忽略行尾空白）。原文一变，该节状态自动降级显示「译文待复核」。

## 被否决的备选

- **翻译进 `wiki/`**：wiki 是 LLM 编译的领域知识层，一个概念一页；译文是逐节线性产物，
  且要能批量重算。混进 wiki 会让"一个概念一页"的规矩失效，也会让 lint 无法区分"知识错"与"翻译错"。
- **翻译进 `sip/raw/`**：`raw/` 是不可变证据（AGENTS.md §2，只追加不改写）。译文会被修订，
  放进去等于破坏证据层。
- **整篇一个大 md 文件**：18 万词，任何一次修改都产生巨型 diff；断点续译也不可能。
- **只存双语 JSON（不落 md）**：md 能被人直接读、被 `marked` 渲染、被 git diff 到句级，
  比自造 schema 便宜。
- **接机器翻译 API 生成初稿**：本机无 key，且 API 不做术语表约束与规范词保留检查；
  由 agent 按 GLOSSARY 逐节译，产出可复核、可回滚。

## 后果

- 得到：中文可对照、可增量、可校验；术语一致性有一个文件可依；原文变更能自动暴露。
- 放弃：译文永远滞后于原文（按需译）；机器初译在长难句语序上可能别扭，需要人读原文复核
  （这也是 `reviewed` 必须由人标的原因）。
- 代价：仓库多一层目录与两个脚本；`AGENTS.md` §2 目录表需要登记 `sip/zh/`（已在
  `docs/memory/open-threads.md` 记为待办，AGENTS.md 只由人改）。
- 重新考虑的触发条件：
  1. 有权威机构发布 RFC 3261 的官方中译（届时以官方为准，本层降级为笔记）
  2. 译文节数超过 200 且 `zh:check` 的"规范词数量不符"长期压不下去（说明逐节人工裁决不可持续，
     要改成按段落对齐的数据结构）
  3. 站点要公开发布 → 需先补 IETF Trust 版权声明（RFC 3261 是 2002 年版权，不含 2010 年后
     RFC 的 Simplified BSD 许可）
