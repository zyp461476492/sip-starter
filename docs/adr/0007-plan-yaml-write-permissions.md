# ADR-0007 plan.yaml 的分级写入权限

状态：current ｜ 日期：2026-11-16

## 背景

`AGENTS.md` §2 把 `plan/plan.yaml` 与 `vocab/terms.yaml` 并排放在"仅人可写"一栏。
但两条禁令的依据不同：

- `vocab/terms.yaml`：ADR-0003 明确"候选池与正式本分离，LLM 只能写候选池"，否则词库变质
- `plan/plan.yaml`：ADR-0003 只规定它是唯一数据源、站点与脚本只消费它，**没有规定谁能写**

实际摩擦来自 M4.7 会话：`l0-1` 的 `done_when` 要求"说出 UAC/UAS/代理/registrar 各自维护什么状态"，
而它的 `sources` 只有 §4 / §24.1 / §24.2 —— §4 讲拓扑与流程，状态定义在 §6 / §12.1.1 / §12.1.2 /
§18.2.1，判据在指定材料下无法完成。agent 无法自行修正，只能把 YAML 片段交给用户手粘。
计划细节的维护成本落在人身上，而人恰恰是最少碰细节的一方。

同时存在一个反向风险：`done_when` 与 `status` 是**自我评分**。
若 agent 既能改判据又能改状态，"未达成"可以合法地变成"改宽判据后达成"，进度条随之失真。
本次会话就出现过一次：agent 建议收窄 `done_when` 并同时标 `done`，由用户批准才落地。

## 决定

`plan/plan.yaml` 的写入权限按字段分三档：

| 字段 | 权限 | 理由 |
|---|---|---|
| `title` / `why` / `prereq` / `sources` / `wiki` / `drills` / `est`，新增与拆分任务 | 人 + agent | 属于计划细节，agent 更清楚锚点与 slug 现状；`npm run check` 可机器校验 |
| `done_when`（判据） | **仅人** | 判据决定"什么算会"，是度量刻度 |
| `status`（`todo` / `doing` / `done`） | **仅人** | 结论，且必须与判据一致 |
| 阶段的 `code` / `timebox`、阶段增删与顺序 | **仅人** | 属于方法论（ADR-0005），改动会影响全部任务 |

agent 可以改的全部是**被校验的客观事实**；不能改的是**评分刻度与结论**。
agent 若认为判据需要改，只能**提议**：把 diff 与理由写进对话或 `docs/memory/open-threads.md`，
由人落笔。`plan.yaml` 顶层 `updated` 由最后修改者更新。

## 备选与否决理由

| 备选 | 否决理由 |
|---|---|
| a) 维持"仅人可写"全部字段 | 缺乏 ADR 依据；把细节维护成本推给最少碰细节的一方；本次已实际卡住计划修正 |
| b) 全部放开，agent 也可改 `status` / `done_when` | 度量自改：判据可回改，"1/32" 不可信；且判据是本仓唯一的"自我评分"环节 |
| c) 交给脚本自动判定 `done` | 判据多为"能画/能说/能指出来"，机器只能校验 slug 存在（`site/build.mjs` 现状），无法验证是否真的会 |
| d) 保留人工确认但用 PR review 机制 | 单人项目、无 PR 流程，成本高于收益（ADR-0002 同类取舍） |

## 后果

- 得到：计划细节由 agent 维护，人只在"这算不算会"上做一次确认；进度条仍然可信
- 放弃：agent 不能自行结项，每个任务收尾需要人一句明确答复
- 代价：`AGENTS.md` §2 的目录表要拆成三行（元数据 / 判据与状态 / 词库正式本）
- **重新考虑的触发条件**：当某个任务的判据能变成**可执行验证**（`sip/labs/drills/` 下的脚本自动跑通）
  时，该任务的 `status` 可对 agent 开放，判据仍归人——即"机器可验的结项"与"人判断的结项"分开授权
