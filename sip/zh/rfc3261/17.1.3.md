当客户端一侧的传输层收到一个响应时，它必须先判定该响应归哪个客户端事务处理，之后才能按 §17.1.1 与 §17.1.2 处理。判定依据是顶层 Via 头域里的 branch 参数。响应匹配某个客户端事务需满足两个条件：

1. 响应顶层 Via 头域里的 branch 参数值，与创建该事务的那个请求的顶层 Via 头域 branch 参数值相同。

2. CSeq 头域里的 method 参数与创建该事务的请求的方法相同。之所以需要 method，是因为 CANCEL 请求构成一个不同的事务，却共享同一个 branch 参数值。

若请求是经组播发出的，可能出现多个服务端各自回多个响应。这些响应的顶层 Via 里 branch 参数都相同，只有 To tag 不同。按上述规则，收到的第一个响应被采用，其余视为重传。这不属于错误；组播 SIP 只提供"类似单跳发现"的初级服务，且只处理单个响应。细节见 §18.1.1。
