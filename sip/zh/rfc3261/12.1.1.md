当服务端（UAS）用一个能建立对话的响应（例如对 INVITE 的 2xx）回应一个请求时，UAS MUST 把该请求中所有 Record-Route 头域值原样复制进响应（包括其中的 URI、URI 参数，以及所有 Record-Route 头域参数，无论 UAS 认不认识），并且 MUST 保持这些值的顺序。UAS MUST 在响应里加上一个 Contact 头域。该 Contact 头域给出的地址，是 UAS 希望对话内后续请求（对 INVITE 而言，还包括 2xx 的 ACK）被送到的地方。通常该 URI 的 host 部分是主机的 IP 地址或 FQDN。Contact 头域里给出的 URI MUST 是 SIP 或 SIPS URI。如果发起该对话的请求，其 Request-URI、或顶层 Record-Route 头域值（如果有）、或（当没有 Record-Route 时）Contact 头域里含有 SIPS URI，则响应中的 Contact 头域 MUST 是 SIPS URI。该 URI SHOULD 具有全局作用域（即同一个 URI 也能用于本对话之外的消息）。同样地，INVITE 里 Contact 头域的 URI 其作用域也不限于本对话，因此即使在本对话之外，它也可以用于发给 UAC 的消息。

随后 UAS 构造对话的状态。该状态 MUST 在对话存续期间保持。

若请求经 TLS 到达，且 Request-URI 含 SIPS URI，则 `secure` 标志置为 TRUE。

路由集 MUST 设为请求中 Record-Route 头域里的 URI 列表，按原顺序、保留所有 URI 参数。若请求里没有 Record-Route 头域，路由集 MUST 置为空集。这个路由集（即使为空）会覆盖本对话内后续请求原先已有的任何路由集。远端目标 MUST 设为请求中 Contact 头域的 URI。

远端序列号 MUST 设为请求 CSeq 头域里序列号的值。本地序列号 MUST 为空。对话 ID 的 call identifier 部分 MUST 设为请求中 Call-ID 的值。对话 ID 的 local tag 部分 MUST 设为该请求的响应里 To 字段中的 tag（响应里的 To 总是带 tag），对话 ID 的 remote tag 部分 MUST 设为请求里 From 字段的 tag。UAS MUST 准备好接收 From 字段不带 tag 的请求，此时该 tag 视为取值 null。

> 这是为了与 RFC 2543 保持向后兼容——它没有强制要求 From tag。

远端 URI MUST 设为 From 字段里的 URI，本地 URI MUST 设为 To 字段里的 URI。
