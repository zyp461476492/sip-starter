当客户端（UAC）发出一个能建立对话的请求（例如 INVITE）时，它 MUST 在请求的 Contact 头域里给出一个具有全局作用域的 SIP 或 SIPS URI（即同一个 SIP URI 也能用于本对话之外的消息）。若请求的 Request-URI、或顶层 Route 头域值含 SIPS URI，则 Contact 头域 MUST 含 SIPS URI。

当 UAC 收到一个能建立对话的响应时，它构造对话的状态。该状态 MUST 在对话存续期间保持。

若请求是经 TLS 发出的，且 Request-URI 含 SIPS URI，则 `secure` 标志置为 TRUE。

路由集 MUST 设为响应中 Record-Route 头域里的 URI 列表，按逆序、保留所有 URI 参数。若响应里没有 Record-Route 头域，路由集 MUST 置为空集。这个路由集（即使为空）会覆盖本对话内后续请求原先已有的任何路由集。远端目标 MUST 设为响应中 Contact 头域的 URI。

本地序列号 MUST 设为请求 CSeq 头域里序列号的值。远端序列号 MUST 为空（它等到远端 UA 在对话内发请求时才建立）。对话 ID 的 call identifier 部分 MUST 设为请求中 Call-ID 的值。对话 ID 的 local tag 部分 MUST 设为请求里 From 字段的 tag，对话 ID 的 remote tag 部分 MUST 设为响应里 To 字段的 tag。UAC MUST 准备好接收 To 字段不带 tag 的响应，此时该 tag 视为取值 null。

> 这是为了与 RFC 2543 保持向后兼容——它没有强制要求 To tag。

远端 URI MUST 设为 To 字段里的 URI，本地 URI MUST 设为 From 字段里的 URI。
