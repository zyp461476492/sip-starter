头域遵循 RFC 2822 [3] §2.2 给出的那套通用头格式。每个头域由字段名、冒号（`:`）与字段值构成。

```
      field-name: field-value
```

§25 规定的 message-header 形式语法允许冒号两侧出现任意数量的空白；不过实现应避免在字段名与冒号之间加空格，并在冒号与字段值之间只用一个空格（SP）。

```
      Subject:            lunch
      Subject      :      lunch
      Subject            :lunch
      Subject: lunch
```

因此上面几种写法都合法且等价，但最后一种才是推荐形式。

头域可以跨多行扩展，办法是在每个续行前至少放一个 SP 或水平制表符（HT）。换行与下一行行首的空白一并视为单个 SP 字符。因此下面两种写法等价：

```
      Subject: I know you're there, pick up the phone and talk to me!
      Subject: I know you're there,
               pick up the phone
               and talk to me!
```

字段名不同的头域之间，相对顺序不重要。不过 RECOMMENDED 的是：代理处理所需的头域（例如 Via、Route、Record-Route、Proxy-Require、Max-Forwards 与 Proxy-Authorization）尽量出现在消息靠前的位置，以便快速解析。字段名相同的头域行之间，相对顺序则重要。当且仅当某头域整个字段值被定义为逗号分隔列表（即遵循 §7.3 定义的语法）时，该字段名相同的多行头域行才 MAY 出现在同一条消息里。这些多行 MUST 能被合并成一个 `field-name: field-value` 对而不改变消息语义——做法是把后续每个字段值依次追加到第一个后面，彼此以逗号分隔。此规则的例外是 WWW-Authenticate、Authorization、Proxy-Authenticate 与 Proxy-Authorization 头域：这些字段名相同的多行 MAY 出现在同一条消息里，但由于它们的语法不遵循 §7.3 列出的通用形式，它们 MUST NOT 被合并成一行头域。

对同名多行头域，无论采用“每行一个值”还是“逗号分隔值”的哪种组合形式，实现 MUST 都能处理。

下面几组头域行合法且等价：

```
      Route: <sip:alice@atlanta.com>
      Subject: Lunch
      Route: <sip:bob@biloxi.com>
      Route: <sip:carol@chicago.com>

      Route: <sip:alice@atlanta.com>, <sip:bob@biloxi.com>
      Route: <sip:carol@chicago.com>
      Subject: Lunch

      Subject: Lunch
      Route: <sip:alice@atlanta.com>, <sip:bob@biloxi.com>,
             <sip:carol@chicago.com>
```

下面每一块都合法，但彼此不等价：

```
      Route: <sip:alice@atlanta.com>
      Route: <sip:bob@biloxi.com>
      Route: <sip:carol@chicago.com>

      Route: <sip:bob@biloxi.com>
      Route: <sip:alice@atlanta.com>
      Route: <sip:carol@chicago.com>

      Route: <sip:alice@atlanta.com>,<sip:carol@chicago.com>,
             <sip:bob@biloxi.com>
```

头域值（header field-value）的格式按头域名逐个定义。它总是下列两种之一：不透明的 TEXT-UTF8 八位组序列，或空白、token、分隔符与带引号字符串的组合。许多现有头域都遵循“一个值 + 若干分号分隔的 parameter-name/parameter-value 对”这一通用形式：

```
         field-name: field-value *(;parameter-name=parameter-value)
```

尽管一个头域值上可挂任意多的参数对，任何给定的 parameter-name MUST NOT 出现一次以上。

比较头域时，字段名一律大小写不敏感。除非某个头域的定义另有说明，字段值、参数名与参数值都大小写不敏感。token 一律大小写不敏感。除非另有说明，以带引号字符串表达的值大小写敏感。例如

```
      Contact: <sip:alice@atlanta.com>;expires=3600
```

等价于

```
      CONTACT: <sip:alice@atlanta.com>;ExPiReS=3600
```

而

```
      Content-Disposition: session;handling=optional
```

等价于

```
      content-disposition: Session;HANDLING=OPTIONAL
```

但下面两个头域并不等价：

```
      Warning: 370 devnull "Choose a bigger pipe"
      Warning: 370 devnull "CHOOSE A BIGGER PIPE"
```
