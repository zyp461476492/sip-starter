Via 头域记录请求到目前为止走过的路径，同时指明响应路由应当走的路径。Via 头域值里的 branch ID 参数充当事务标识符，代理用它来检测环路。

一个 Via 头域值包含：发送该消息所用的传输协议、客户端的域名或网络地址，可能还有它希望接收响应的端口号。Via 头域值还可以带 `maddr`、`ttl`、`received`、`branch` 等参数，其含义与用法在别处描述。对于符合本规范的实现，branch 参数的值 MUST 以魔法 cookie `z9hG4bK` 开头，如 §8.1.1.7 所述。

此处定义的传输协议有 `UDP`、`TCP`、`TLS` 与 `SCTP`。`TLS` 表示基于 TCP 的 TLS。当请求发往 SIPS URI 时，协议部分仍写 `SIP`，而传输协议为 TLS。

```
Via: SIP/2.0/UDP erlang.bell-telephone.com:5060;branch=z9hG4bK87asdks7
Via: SIP/2.0/UDP 192.0.2.1:5060 ;received=192.0.2.207
     ;branch=z9hG4bK77asjd
```

Via 头域的紧凑形式为 `v`。

在这个例子里，消息来自一台有两个地址（192.0.2.1 与 192.0.2.207）的多宿主主机。发送方猜错了实际会走哪个网络接口。Erlang.bell-telephone.com 发现了这个不一致，于是在前一跳的 Via 头域值上追加了一个参数，写入报文实际来自的地址。

域名或网络地址与端口号不必遵循 SIP URI 语法。具体而言，`:` 或 `/` 两侧允许出现 LWS，如下例：

```
   Via: SIP / 2.0 / UDP first.example.com: 4000;ttl=16
     ;maddr=224.2.0.1 ;branch=z9hG4bKa7c6a8dlze.1
```

尽管本规范强制要求所有请求都带 branch 参数，该头域的 BNF 却把它标为可选。这是为了能与 RFC 2543 实体互通——那些实体不要求插入 branch 参数。

两个 Via 头域相等，当且仅当它们的 sent-protocol 与 sent-by 字段相等、两边参数集合相同、且所有参数的值都相等。
