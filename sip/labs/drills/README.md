# drills

本仓库不写实现代码（ADR-0004）。`drills/` 只放**最小验证件**：
证明"我确实理解了这条协议行为"，验证完就可以扔掉。

## 为什么要有它

读 spec 不会让人记住 `MUST`；被自己的代码咬一次才会。所以每个里程碑配一个 drill，
drill 的判据必须是**可执行/可对照的**，不是"我读完了"。

## 格式

每个 drill 一个 markdown 文件，slug 小写连字符（`plan.yaml` 的 `drills:` 引用它）：

```markdown
---
slug: msg-parse
phase: alpha
specs: ["RFC3261 §7.1", "RFC3261 §7.3"]
wiki: ["specs/rfc3261"]
---

## 目标
（一条协议行为，一句话）

## 输入
（用哪段原文/哪个报文做夹具，出处锚点）

## 做法
（步骤，不贴完整实现代码）

## 判据
（怎么算通过：字节级一致 / 状态迁移与图一致 / 工具输出）

## 我踩到的
（做完立刻填：哪条我以为懂了其实没有）
```

## 规矩

1. **不复制原文大段**，用 `sip/raw/` 的锚点引用
2. 判据里禁止出现"理解了""掌握了"这类不可验证的词
3. 做完把"我踩到的"回写进 wiki 对应页，或记入 `docs/memory/facts.md`
