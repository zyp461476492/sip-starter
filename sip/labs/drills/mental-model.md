# drill: 五个"为什么"

## 目标

用五个问题检验一件事：**你是"知道 SIP 长什么样"，还是"知道它为什么长这样"**。
后者才有判断力——写 parser 时才不会把设计取舍当成怪癖。

## 输入

`sip/raw/rfc/rfc3261.txt` 的 §1–§6（Phase 0 的 p0-1 到 p0-3 已覆盖）。
答案必须来自原文，**不许用自己的话复述**（那正是我们禁止的"摘要"）。

## 做法

1. 先合上 wiki，凭理解把五题的答案写下来（允许写"不知道"）
2. 逐题回原文找依据，把**原文句子**抄进 `wiki/concepts/sip-mental-model.md`，紧跟锚点
3. 每题补一句"所以实现上意味着什么"
4. 写不出来的题，记进 `open-threads.md`，不要编

## 判据

| # | 问题 | 通过标准 |
|---|---|---|
| 1 | Via 逐跳 vs To/From 端到端 | 能说出响应为什么必须沿原路回，以及为什么发起方不能预知路径 |
| 2 | 2xx 后 ACK 不属于事务 | 能解释"要投递所有 200 OK"与 forking 的关系 |
| 3 | 对话 ID 两端各一个 tag | 能解释单方定义为什么无法区分 forking 产生的多个对话 |
| 4 | 媒体不在 SIP 里 | 能说出 SIP 只做信令这件事换来了什么（可演进、可混搭） |
| 5 | 无状态代理无事务 | 能说出事务状态的代价与无状态转发的适用场景 |

五题都能**带锚点**作答 → `wiki/concepts/sip-mental-model.md` 升 `status: current`。
