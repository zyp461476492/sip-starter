# RFC 3261 章节地图

一句话：**269 页不是一本书，是四类文档缝在一个文件里**。按类型读，不按页码读。

> 本文是"提炼重点"的正确形态：产出**路线**，不产出**摘要**。摘要会转述 `MUST` 而走形（见
> `AGENTS.md` §3），路线不会。

## 前提：贯穿全文的两个分层

- **信令面 / 媒体面完全解耦**：SDP 只是协商，媒体走 RTP，跟 SIP 事务无关
- **UAC/UAS / 代理 / B2BUA 是三种形态**：事务层只存在于 UA 与有状态代理中（§17 原文明确无状态代理无事务）
- 自研栈的实现顺序必须是 **报文 → 事务 → 对话 → 应用（B2BUA）**，反过来一定返工

## 四条阅读路线

0. **Phase 0 认知地基（2–3 小时，开工前置）**：§1–§3 通读 → §5 通读 → §6 精读 → §4 精读 → §24 通读。
   产出 `wiki/concepts/sip-mental-model.md` + 五个“为什么”答得上（见 `sip/labs/drills/mental-model.md`）。
1. **α 之前（半天）**：§7 → §7.5 → §18（配合 §24 报文做夹具）。目标：能写出可 round-trip 的 parser。
2. **β 之前（2–3 天）**：§17 全部 + 附录 A Table 4 + §18。目标：能默画四套状态机与全部定时器。
3. **其余按里程碑取**：见上表的"服务"列。**不要提前读**——读了也不进脑子。

## 陷阱清单（都在边缘条款，摘要一定会漏）

| 坑 | 出处 | 症状 |
|---|---|---|
| ACK 有两套规则 | §17.1.1.3 | 非 2xx 的 ACK 走事务层（复用 branch），2xx 的 ACK 由 core 生成、自成事务 |
| 2xx 可能有多份 | §13.1、§4 | forking 时每个 2xx 建立不同对话，但属于同一通呼叫 |
| TCP 的 framing | §7.5 | 没有 Content-Length 就无法切分消息 |
| CANCEL 的竞态 | §9 | 最终响应已发出后 CANCEL 无效 |
| 对话内请求路径 | §12.2、§16.6 | Record-Route 决定 Route 集，用错方向就发不出去 |
